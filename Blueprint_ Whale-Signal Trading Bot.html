Blueprint: Whale-Signal Meme Coin Trading Bot

Dokumen ini adalah spesifikasi teknis untuk diserahkan ke Claude (Code) sebagai brief pengerjaan. Berisi arsitektur, alur data, scoring engine, state machine approval/timeout, dan catatan keamanan.

⚠️ Catatan sebelum mulai

  • Bot ini akan mengeksekusi transaksi on-chain nyata dengan uang nyata. Bug logic = kehilangan dana secara instan.
  • Skor "kelayakan" bukan prediksi harga — hanya filter risiko on-chain (liquidity, distribusi holder, keamanan kontrak). Token dengan skor tinggi tetap bisa turun ke nol.
  • Mulai dari testnet / dummy wallet / paper trading dulu sebelum wire ke wallet asli.
  • Private key tidak boleh disimpan di kode, repo, atau plaintext di server — pakai secret manager / KMS / hardware wallet signer.

1. Ringkasan Alur

Whale Wallet Watcher
        │ (deteksi wallet target beli token baru)
        ▼
Token Data Aggregator ──► Scoring Engine ──► skor ≥ 80?
        (liquidity, holder,                      │
         kontrak, volume)                         │ ya
                                                   ▼
                                  Telegram Alert: [Approve] [Skip]
                                                   │
                              ┌────────────────────┴────────────────────┐
                              │ approve dalam 2 menit                   │ tidak ada respons / timeout
                              ▼                                          ▼
                     Trade Executor: BUY                              tidak beli, arsipkan sinyal
                              │
                              ▼
                   Position Monitor (real-time price)
                     │                        │
          harga turun ≥20%             harga naik ≥100%
          dari entry                          │
                 │                            ▼
                 ▼                 Telegram Alert: [Sell] [Hold]
          AUTO SELL (stop loss)         │
          — tanpa approval               ┌───┴────┐
                                    approve/hold   timeout 2 menit
                                          │             │
                                     ikuti pilihan   AUTO SELL

Prinsip kunci: stop-loss selalu otomatis tanpa approval (karena tujuannya membatasi kerugian cepat), sedangkan take-profit butuh approval karena ada opsi "hold" untuk lanjut naik — dan timeout diam-diam default ke sell, bukan hold (biar aman kalau kamu nggak sempat respon).

2. Komponen Sistem

2.1 Whale Wallet Watcher

  • Input: daftar wallet address yang dipantau (per chain: Solana / EVM).
  • Sumber data:
    • Solana: Helius webhooks / enhanced transaction API
    • EVM: Alchemy/Moralis webhook atau mempool + log listener
  • Trigger event: wallet target melakukan swap beli token yang bukan stablecoin/blue-chip (whitelist exclude: SOL, ETH, USDC, USDT, dst).
  • Output event: {wallet, chain, token_address, tx_hash, timestamp, amount_usd}

2.2 Token Data Aggregator

Begitu ada token baru terdeteksi, kumpulkan data dari:

Data Sumber
Liquidity pool size & lock status DexScreener API / on-chain pool query
Top holder distribution Bubblemaps API atau on-chain query manual
Contract safety (honeypot, mint function, ownership renounced) GoPlus Security API
Volume 24 jam, umur token, jumlah holder DexScreener / Birdeye (Solana)
Riwayat rug/scam token serupa (opsional) Cache internal / heuristik nama mirip

2.3 Scoring Engine

Skor 0–100, kombinasi weighted dari beberapa faktor. Contoh bobot (harus bisa dikonfigurasi, bukan hardcode):

Faktor Bobot Catatan
Liquidity locked & size 25% 0 kalau tidak locked / <$10K
Top 10 holder concentration 20% makin rendah % makin baik
Contract safety (honeypot/mint/renounce) 25% 0 otomatis kalau honeypot terdeteksi (hard fail)
Volume/Market cap ratio 15% volume rendah vs cap tinggi = red flag
Umur token & jumlah holder 15% token baru <1 jam dapat penalti
  • Hard fail rules (skor langsung dipaksa ke bawah threshold, apapun bobot lain): honeypot terdeteksi, liquidity tidak locked & <$5K, kontrak tidak bisa di-fetch/verifikasi.
  • Threshold approval: ≥ 80 → trigger alert Telegram untuk approve beli.
  • Simpan breakdown skor (bukan cuma angka akhir) supaya alert Telegram bisa tampilkan alasan.

2.4 Telegram Bot (Approval Layer)

  • Alert masuk berisi: nama token, alamat, skor + breakdown, liquidity, top10%, link chart (DexScreener), tombol inline Approve / Skip.
  • State per sinyal: pending → approved / skipped / timeout_expired
  • Timeout 2 menit dari pesan alert dikirim:
    • Jika tidak ada respons → status timeout_expired, tidak beli, log sebagai missed signal (bukan auto-buy).
    • (Catatan: untuk fase BUY, kamu minta approve manual — beda dengan fase SELL take-profit yang defaultnya auto-sell saat timeout. Konfirmasi ke Claude Code perilaku mana yang kamu mau untuk fase buy: default skip, seperti di atas, atau ingin auto-buy juga saat timeout? Saran saya: skip, karena beli otomatis tanpa approval lebih berisiko daripada menahan profit.)

2.5 Trade Executor

  • Solana: Jupiter Aggregator API untuk swap
  • EVM: 1inch / 0x API untuk swap
  • Parameter wajib per eksekusi:
    • Slippage tolerance (default misal 5–10% untuk meme coin, harus dikonfigurasi)
    • Max gas / priority fee cap
    • Position size (fixed USD amount per trade, atau % dari portfolio — jangan all-in)
    • Simpan entry_price, entry_amount, tx_hash, timestamp begitu order fill

2.6 Position Monitor

  • Poll harga token setiap X detik (misal 10–15 detik) via DexScreener/Birdeye price feed selama posisi terbuka.
  • Hitung pnl_percent = (current_price - entry_price) / entry_price * 100
  • Logic:
    • pnl_percent <= -20% → AUTO SELL langsung, tanpa approval, eksekusi sesegera mungkin. Kirim notifikasi Telegram setelah eksekusi (bukan sebelum).
    • pnl_percent >= 100% → kirim Telegram alert [Sell] [Hold] dengan timeout 2 menit:
      • Approve/Sell ditekan → jual sekarang
      • Hold ditekan → reset timer, lanjut pantau, alert baru akan muncul lagi di kelipatan berikutnya (misal tiap +50% lagi) supaya tidak kelewat begitu saja
      • Timeout 2 menit tanpa respons → AUTO SELL (default aman, sesuai request kamu)

2.7 State Machine Approval (ringkasan)

BUY SIGNAL FLOW
pending ──approve──► executing_buy ──filled──► position_open
   │
   └──timeout/skip──► archived (no action)

SELL SIGNAL FLOW (take-profit only; stop-loss tidak lewat state ini)
profit_alert_sent ──approve/sell──► executing_sell ──filled──► position_closed
   │
   ├──hold──► position_open (reset alert threshold)
   │
   └──timeout(2m)──► executing_sell (auto) ──filled──► position_closed

2.8 Data & Logging

  • Database (Postgres/SQLite cukup untuk skala personal): tabel signals, scores, positions, trades, telegram_interactions.
  • Log semua keputusan otomatis (stop loss, timeout auto-sell) dengan timestamp + alasan — penting untuk audit kalau ada bug.
  • Dashboard (bisa reuse mockup UI yang sudah dibuat sebelumnya) untuk lihat posisi terbuka, riwayat, dan performa skor vs hasil aktual (buat evaluasi apakah threshold 80 perlu disesuaikan).

3. Keamanan & Operasional

  • Private key wallet trading disimpan di secret manager (AWS Secrets Manager / GCP Secret Manager / Vault), bukan .env di server yang sama dengan webapp publik.
  • Pisahkan wallet trading dari wallet utama — isi hanya sejumlah dana yang siap dipakai/hilang.
  • Rate limit & circuit breaker: kalau dalam 1 jam ada >N auto-sell stop-loss beruntun, hentikan sementara auto-buy baru (indikasi kondisi pasar buruk atau bug).
  • Idempotency: pastikan webhook whale watcher tidak memicu eksekusi ganda untuk event yang sama (dedupe by tx_hash).
  • Uji slippage & gas di kondisi network congested — meme coin sering di chain yang volatile fee-nya.

4. Tech Stack (Final)

MVP starter stack (rekomendasi mulai dari sini): Node.js + TypeScript + BullMQ/Redis + Supabase (Postgres) + Helius + Jupiter + GoPlus + grammY, deploy di Railway. Semua ada free/murah tier untuk testing sebelum commit modal besar.

5. Rencana Build Per-Batch

Jangan minta Claude Code kerjakan semuanya sekaligus dalam satu prompt — pecah jadi batch di bawah, dan selesaikan + tes tiap batch dulu sebelum lanjut ke batch berikutnya. Setiap batch punya "definisi selesai" (acceptance criteria) supaya jelas kapan boleh lanjut.

Batch 1 — Project Scaffold & Infra Dasar

  • Setup repo Node.js + TypeScript, struktur folder (/services, /workers, /bot, /db, /dashboard)
  • Setup PostgreSQL (Supabase) + migration awal: tabel signals, scores, positions, trades, telegram_interactions
  • Setup Redis + BullMQ, buat 1 job dummy untuk pastikan queue jalan
  • Setup env/secret management (Doppler atau env terenkripsi) — belum isi private key asli
  • ✅ Selesai kalau: server nyala, bisa connect ke DB, job dummy di BullMQ berhasil jalan & tercatat di log

Batch 2 — Whale Wallet Watcher

  • Integrasi Helius webhook (Solana) dan/atau Alchemy webhook (EVM) sesuai chain yang kamu pilih
  • Filter event: hanya swap beli token non-stablecoin/non-blue-chip
  • Simpan event mentah ke tabel signals (status: detected)
  • Dedupe by tx_hash supaya event yang sama tidak diproses dua kali
  • ✅ Selesai kalau: transaksi beli dari wallet test masuk ke tabel signals dengan data lengkap (token address, wallet, amount, timestamp), sudah dites pakai wallet asli di jaringan tapi tanpa eksekusi apa pun setelahnya

Batch 3 — Token Data Aggregator

  • Begitu ada signals baru, fetch: liquidity + lock status, top holder distribution, contract safety, volume 24 jam, umur token, jumlah holder
  • Simpan hasil mentah tiap sumber ke tabel terpisah atau kolom JSON di signals
  • Handle API gagal/timeout (retry + fallback, jangan crash worker)
  • ✅ Selesai kalau: untuk 5 token uji coba (campur token bagus & token jelek/rug), semua data metric berhasil ke-fetch dan tersimpan, error handling teruji dengan cara matikan salah satu API key sementara

Batch 4 — Scoring Engine

  • Implementasi rumus skor sesuai tabel bobot di bagian 2.3, termasuk hard-fail rules
  • Simpan breakdown skor (bukan cuma angka akhir) ke tabel scores
  • Bikin config file terpisah untuk bobot & threshold (jangan hardcode) supaya gampang diubah nanti
  • ✅ Selesai kalau: jalankan scoring terhadap 5 token uji Batch 3, hasil skor & breakdown masuk akal secara manual kamu cek satu-satu (token rug dapat skor rendah, token dengan liquidity locked & holder tersebar dapat skor lebih tinggi)

Batch 5 — Telegram Bot: Approval Beli

  • Setup bot grammY, kirim alert format sesuai bagian 2.4 (skor, breakdown, liquidity, top10%, link chart, tombol Approve/Skip)
  • Implementasi state machine: pending → approved / skipped / timeout_expired
  • Timeout 2 menit pakai delayed job BullMQ
  • Belum ada eksekusi swap asli — approve/skip cuma update status di DB dan reply ke chat, biar alur approval teruji dulu tanpa risiko dana
  • ✅ Selesai kalau: skor ≥80 dari Batch 4 memicu alert Telegram, tombol Approve/Skip berfungsi, timeout 2 menit teruji berjalan otomatis kalau didiamkan

Batch 6 — Trade Executor (BUY)

  • Integrasi Jupiter API (dan/atau 1inch) untuk eksekusi swap beli
  • Ambil parameter: slippage tolerance, max gas/priority fee, position size dari config
  • Simpan entry_price, entry_amount, tx_hash ke tabel positions & trades setelah fill
  • Test di jumlah sangat kecil / testnet dulu sebelum posisi ukuran normal
  • ✅ Selesai kalau: approve dari Batch 5 berhasil trigger swap beli asli di jaringan (jumlah kecil), data posisi tersimpan benar, slippage/gas sesuai config

Batch 7 — Position Monitor & Auto-Sell

  • Worker polling harga tiap 10–15 detik untuk semua positions berstatus open
  • Logic stop-loss (-20% → auto sell langsung, notifikasi setelah eksekusi)
  • Logic take-profit (+100% → alert Sell/Hold, timeout 2 menit → auto-sell, hold → reset ke kelipatan berikutnya)
  • ✅ Selesai kalau: simulasikan (atau tunggu kejadian asli di jumlah kecil) kedua skenario stop-loss dan take-profit, keduanya berjalan sesuai state machine di bagian 2.7, semua keputusan otomatis tercatat di log dengan alasan

Batch 8 — Dashboard & Monitoring

  • Hubungkan dashboard (reuse mockup yang sudah ada) ke data asli: posisi terbuka, riwayat trade, breakdown skor
  • Tambah view sederhana untuk evaluasi performa (skor vs hasil aktual) — membantu kamu tuning threshold nanti
  • ✅ Selesai kalau: dashboard menampilkan data real dari DB, bisa dipakai untuk cek status tanpa buka Telegram/DB manual

Batch 9 — Hardening & Keamanan

  • Circuit breaker: hentikan auto-buy baru kalau ada >N stop-loss beruntun dalam 1 jam
  • Audit logging lengkap untuk semua keputusan otomatis
  • Review penyimpanan private key (pastikan benar-benar tidak plaintext/ke-commit)
  • Uji ulang seluruh alur end-to-end dengan dana kecil sebelum scale up
  • ✅ Selesai kalau: semua checklist keamanan di atas lolos, dan sudah ada minimal 1 siklus penuh (deteksi → skor → approve → beli → stop-loss atau take-profit → jual) berjalan mulus dengan dana kecil

6. Hal yang Perlu Kamu Putuskan Sebelum Serah ke Claude Code

  2. Ukuran posisi per trade (fixed USD atau % portfolio)?
  3. Slippage tolerance default?
  4. Perilaku timeout di fase beli (bukan take-profit): skip (disarankan) atau auto-buy?
